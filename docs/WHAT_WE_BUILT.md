## 4. Replay Engine (Task 1 & 1B)
- Created `engine/replay.py`.
- **Details:**
  - Accepts `--old`, `--new`, `--tags`, and `--app` arguments.
  - Generates temporary Git worktrees to checkout the old and new app versions.
  - Boots both versions concurrently via `subprocess` using `uvicorn` on ports 8001 and 8002.
  - Polls `/health` endpoints to ensure readiness before execution.
  - Parses the `scenarios/` folder, filtering by requested tags.
  - Exits with an error if no scenarios match the requested tags (as required by Task 1B).
  - Iterates through the matched scenarios sequentially, making HTTP requests to both local servers via `httpx`.
  - Aggregates the responses and writes a strictly formatted `results.json`.
  - Ensures clean shutdown of child processes and deletion of temporary worktrees.
- **Verification:** Tested successfully running `python -m engine.replay --old HEAD --new HEAD --tags emi --app stub.app:app`. Booted the servers, matched 2 scenarios, ignored the third, and produced a valid `results.json`. Tested failing correctly when passed `nosuchtag`.

## 5. Comparison Engine (Task 2)
- Created `engine/compare.py`.
- **Details:**
  - Reads `results.json` to perform a semantic diff of old vs. new responses.
  - Identifies drift if HTTP status codes differ.
  - Deep-walks JSON trees to compare values, utilizing dot-notation for paths (e.g., `schedule.0.interest`).
  - Ignores fields matching specific noise keys (`request_id`, `generated_at`, `trace_id`), standard UUID regex patterns, or ISO timestamp regex patterns, regardless of whether they appear as keys or as string values.
  - Accounts for floating-point math issues by comparing numeric values with a `< 0.01` tolerance.
  - Assigns a verdict of `identical` or `drift` for each scenario, collecting the exact list of differing fields formatted exactly as specified in `CONTRACTS.md`.
  - Implements a `--selftest` flag with three built-in test fixtures (noise-only, real drift, float tolerance).
- **Verification:** `python -m engine.compare --selftest` passes successfully. `python -m engine.compare --results results.json` evaluates the dummy results accurately as `identical`, successfully ignoring the differing UUIDs and timestamps generated by `stub/app.py`.
